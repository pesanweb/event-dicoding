Kriteria Opsional

Selain kriteria utama, terdapat kriteria opsional yang yang dapat Anda penuhi agar mendapat nilai yang lebih tinggi.

  1. Membuat Fitur Pengaturan Daily Reminder

    • Menambahkan menu pengaturan daily reminder untuk event aktif terdekat.

      • Anda bisa menggunakan endpoint untuk menampilkan event aktif kemudian mengambil satu data pertama, atau

      • Menggunakan parameter limit pada endpoint. Misalnya:
        https://event-api.dicoding.dev/events?active=-1&limit=1

    • Menggunakan WorkManager untuk membuat Periodic Work dengan interval 1 hari.

    • Notifikasi berisi data berupa nama dan waktu event terdekat.

    • Pastikan notifikasi hanya tampil ketika menu pengaturan notifikasi dalam keadaan aktif.

  2. Mengimplementasikan Repository dan Injection

    • Menerapkan Repository dan Injection dengan benar untuk data yang diambil dari API. 

  3. Mengimplementasikan Coroutine

    • Menggunakan Coroutine untuk implementasi Retrofit dan Room.

  4. Mengimplementasikan Error Handling

    • Aplikasi bisa memberikan pesan error jika data tidak berhasil ditampilkan. Misalnya, ketika tidak ada internet atau gagal mendapatkan data dari API.

  5. Meningkatkan Kualitas Kode

    • Warning di Inspect Code (Code → Inspect Code) tidak lebih dari 10 (typo tidak dihitung).

      https://event-api.dicoding.dev/events/{id}

Membuat Tombol Favorite

  • Tambahkan dulu ikon favorite yang bisa didapatkan melalui Vector Asset.
  • Kemudian buat FAB/Tombol/Menu untuk menampilkan ikon tersebut pada halaman detail. Berikut contohnya.
  • Selanjutnya, mulailah membuat Entity, Dao, dan Database seperti pada latihan berikut.
    • Latihan Room
  • Untuk entity, Anda bisa membuat data class berisi minimal dua data saja.
    @Entitydata class FavoriteEvent(
    @PrimaryKey(autoGenerate = false)
    var id: String = "",
    var name: String = "",
    var mediaCover: String? = null,
)
  • Pada langkah awal, Anda bisa menambahkan aksi insert saja dulu ketika tombol Favorite ditekan. Pastikan datanya masuk ke database dengan memantaunya melalui App Inspection → Database Inspector.
  • Selanjutnya untuk mengetahui bahwa suatu user sudah ditambahkan ke dalam database atau belum, Anda bisa menggunakan query seperti ini
    @Query("SELECT * FROM FavoriteEvent WHERE id = :id")    
fun getFavoriteEventById(id: String): LiveData<FavoriteEvent>
    Alhasil, ketika di-observe di halaman detail, Anda bisa membuat logika seperti ini.
    • Jika data null, tampilkan ikon favorite border.
    • Jika data tidak null, tampilkan ikon favorite full.
  • Langkah selanjutnya yaitu menambahkan aksi delete. Pada dasarnya, Anda bisa menggunakan fungsi sebelumnya, yaitu getFavoriteEventById untuk menentukan aksi yang diberikan. 
    • Jika status favorite true, panggil aksi delete.
    • Jika status favorite false, panggil aksi insert.

Menampilkan Halaman Favorite

  • Buat Fragment(destination) baru pada Navigation Component dengan isi yang hampir sama dengan halaman Upcoming/Finished Event (berisi RecyclerView dan ProgressBar).
  • Tambahkan menu Bottom Navigation dan gunakan ikon yang sesuai. Pastikan id pada menu tersebut sama dengan id pada navigation component.

    bottom_nav_menu.xml

    mobile_navigation.xml

    <item
    android:id="@+id/navigation_favorite"
    android:icon="@drawable/baseline_favorite_24"
    android:title="@string/title_favorite" />
    <fragment
    android:id="@+id/navigation_favorite"
    android:name="com.dicoding.myproject.ui.favorite.FavoriteFragment"
    android:label="@string/title_favorite"
    tools:layout="@layout/fragment_favorite" />
  • Tambahkan fungsi untuk mendapatkan data Favorite pada Dao dan Repository.
  • Buat ViewModel dan tambahkan ke ViewModelFactory.
  • Observe data pada Activity dan tampilkan dengan adapter yang sama. Bedanya, karena object yang didapat dari adapter berbeda dengan adapter, Anda perlu mengubahnya dulu seperti ini.
    viewModel.getFavoriteUser().observe(viewLifecycleOwner) { users ->
    val items = arrayListOf<ListEventsItem>()
    users.map {
        val item = ListEventsItem(id = it.id.toInt(), name = it.name, imageLogo = it.mediaCover)
        items.add(item)
    }
    adapter.submitList(items)
}
  • Berikut hasil jadi tampilan dari halaman favorite.

Submission yang Tidak Sesuai Kriteria

Jika submission Anda tidak sesuai dengan kriteria, maka akan ditolak oleh reviewer, berikut poin-poin yang harus diperhatikan:

  • Terkait Project.
    • Project tidak bisa di-build.
    • Aplikasi force closed.
    • Mengirimkan file selain proyek Android Studio.
    • Mengirimkan proyek yang bukan karya sendiri.
    • Mengirimkan berkas Zip di dalam Zip.
  • Tidak memenuhi kriteria yang sudah ditentukan.
    • Terkait halaman detail.
      • Menggunakan WebView untuk menampilkan deskripsi event.
    • Terkait halaman favorite.
      • Data tidak langsung tampil di halaman favorite setelah event ditambahkan.
      • Terdapat item yang duplikat pada halaman favorite.
      • Halaman detail tidak bisa dibuka dari halaman favorite
    • Terkait pengaturan tema.
      • Tidak ada menu pengaturan untuk mengganti tema.
      • Ketika membuka aplikasi dari awal, tema tidak terimplementasi.

Ketentuan Berkas Submission

Beberapa poin yang perlu diperhatikan ketika mengirimkan berkas submission:

  • Menggunakan Android Studio.
  • Menggunakan bahasa pemrograman Kotlin atau Java.
  • Mengirimkan pekerjaan Anda dalam bentuk folder Proyek Android Studio yang telah diarsipkan (ZIP).

Sebelum mengirimkan proyek, pastikan Anda sudah mengekspornya dengan benar. Bagaimana cara ekspor proyek ke dalam berkas ZIP?

  1. Pilih menu File → Export → Export to ZIP File... pada Android Studio.
  2. Pilih direktori penyimpanan dan klik OK.

Dengan cara di atas, ukuran dari berkas ZIP akan lebih kecil dibandingkan Anda melakukan kompresi secara manual pada file explorer.

Ketentuan Proses Review

Beberapa hal yang perlu Anda ketahui mengenai proses review

  • Tim reviewer akan mengulas submission Anda dalam waktu selambatnya 3 (tiga) hari kerja (tidak termasuk Sabtu, Minggu, dan hari libur nasional).

  • Anda akan mendapat notifikasi hasil pengumpulan submission Anda via email, atau Anda dapat mengecek status submission pada akun Dicoding Anda.
